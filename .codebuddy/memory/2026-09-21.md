## 调研：IDEA Diagrams 的 "Go To" 菜单实现 + 给 DataChart 表头右键加跳转的方案

用户问题：IDEA Database 的 ER 图右键菜单里 `Go To > Data / Go to DDL / Database Explorer` 怎么实现的？DataChart 表头右键菜单能否照做？

### 结论（反编译本地 `ideaIU-2023.2.6` 得到，非猜测）

1. **图右键菜单 = 把平台/Database 已有 Action 组装成 ActionGroup**，不是手写逻辑。
   - 基类 `com.intellij.uml.core.actions.DiagramSourceActionsGroup`（在 `plugins/uml/lib/uml-support.jar`）。
   - Database 侧 `com.intellij.database.diagram.DbDiagramProvider$2$1` 匿名子类重写 `getChildren(AnActionEvent)`，直接用
     `ActionManager.getInstance().getAction(pid)` 取 `$Copy` / `CopyReference` / `FindUsages` / `Uml.SourceActionsGroup.QuickActions` / `DbDiagrams.SourceActionsGroup.GoTo` 等，中间插 `Separator.getInstance()`。
   - "Go To" 子菜单定义在 `plugins/DatabaseTools/lib/database-plugin.jar!/META-INF/DatabasePlugin.xml`：
     ```xml
     <group id="DbDiagrams.SourceActionsGroup.GoTo" popup="true">
       <reference ref="Jdbc.OpenEditor.Data"/>
       <reference ref="Jdbc.OpenEditor.DDL"/>
       <reference ref="sql.SelectInDatabaseView"/>
     </group>
     ```
     文案 `group.DbDiagrams.SourceActionsGroup.GoTo.text=Go To`。
   - 真正干活的 action：
     - `Jdbc.OpenEditor.DDL` → `com.intellij.database.actions.OpenEditorAction$OpenDDLAction`
     - `Jdbc.OpenEditor.Data` → `OpenEditorAction$OpenDataAction`（update 里按 place 换文案：place=="EditorPopup" → "Edit Data"，否则 → "Data"，键 `action.Jdbc.OpenEditor.Data.GoTo.text`）
     - `sql.SelectInDatabaseView` → `com.intellij.database.actions.SelectInDatabaseViewAction`（place 非 EditorPopup 时文案 "Database Explorer"）
2. **这些通用 Action 只认 `CommonDataKeys.PSI_ELEMENT`，所以关键是"图能提供 PSI 上下文"**。
   - `com.intellij.uml.UmlFileEditorImpl implements DataProvider`，其 `getData(String, DiagramBuilder)` 把图上选中的 `DiagramNode`（`com.intellij.diagram.PsiDiagramNode` 持有 `SmartPsiElementPointer<PsiElement>`）映射成 PSI 元素。
   - `DiagramDataKeys.BUILDER` → `DiagramSelectionService.getSingleSelectedNode(builder)` 用于判 enable。
3. **陷阱**：`DiagramSourceActionsGroup.update()` 要求 DataContext 里有 `DiagramDataKeys.BUILDER` 且图上必须有选中节点，否则整组 `setEnabledAndVisible(false)` —— 在画板里直接复用 `DbDiagrams.SourceActionsGroup.GoTo` 会被禁用，必须自建 `DefaultActionGroup`。

### 核查过的可用 API（2023.2.6）
- `AnActionEvent.createFromDataContext(String place, Presentation, DataContext)` / `createFromAnAction(action, inputEvent, place, ctx)` 均存在。
- `com.intellij.openapi.actionSystem.impl.SimpleDataContext.builder().add(DataKey, value).build()`；另有 `getProjectContext(project)`。
- `ActionPopupMenu.setDataContext(Supplier<? extends DataContext>)` + `setTargetComponent(JComponent)` 在 2023.2 已有（`ActionManager.createActionPopupMenu(place, group)` 无 component 重载）。
- `ActionPlaces` 2023.2 **没有** `CONTEXT_MENU` 常量；可用 `POPUP` / `UNKNOWN`。
- Database 侧反射链：`DbPsiFacade.getInstance(Project)` → `findDataSource(String)` → `findElement(DasObject)` → `DbElement`（PSI）；表列表用 `DasUtil.getTables(DasDataSource)`。
- `com.intellij.database.psi.DbElement extends PsiFileSystemItem`（即 PsiElement，有 getName/getVirtualFile）。

### 给 DataChart 的落地方案（本次只出方案，未改代码）
- 新增 `com.wd.db.TableNavigator`（反射静态工具）：`resolveDbElement(project, TableInfo)` + `performAction(project, TableInfo, actionId)`。
- **不持久化 PSI 元素**（重启/同步后失效），右键时用 `TableInfo` 的 datasource+schema+tableName 现场重新解析，天然兼容旧文件与重启。
- `BoardContextMenu.buildHeaderMenu` 增加回调（与现有 `onSyncStructure`/`onDeleteTable` 同风格），`KanbanBoard.showHeaderContextMenu` 桥接。
- 菜单项建议走"自己加 JMenuItem + 调 `action.update` 判 enable"路线，保持与现有菜单的 hover 配色/字体一致（用户规则 3）；若要子菜单则自建 `DefaultActionGroup` + `ActionPopupMenu#setDataContext`。
- 未装 Database 插件时 `ActionManager.getAction(...)` 返回 null，需降级禁用菜单项。

### 根因 1：`sql.SelectInDatabaseView` 用合成 AnActionEvent 会被静默置灰
反编译调用链：
```
SelectInDatabaseViewAction.update()
  → SelectInContextImpl.createContext(event)
  → new SelectInDatabaseView().canSelect(ctx, isStrict(dataContext))
  → presentation.setEnabledAndVisible(...)
canSelect(ctx, strict) = !ctx.getVirtualFile().isDirectory() && askProvidersInner(ctx, strict) != null
askProvidersInner = 遍历 com.intellij.database.selectInProvider 扩展的 findTarget(ctx, strict)
DbElementSelectInProvider.findTarget: if (!DbImplUtil.isDatabaseVirtualFile(ctx.getVirtualFile())) return null;
```
即 **ctx 的虚拟文件必须属于 Database 文件系统**，合成 AnActionEvent（无 VIRTUAL_FILE / CONTEXT_COMPONENT）构造不出 → 置灰。

### 修复 1：改直连 `DatabaseView.select(PsiElement, boolean)`
`com.intellij.database.view.DatabaseView` 的 **public static** `select(PsiElement, boolean)` 就是 `SelectInDatabaseView.selectIn` 内部真正调用的那一步。
`TableNavigator` 对 `ACTION_SELECT_IN_DATABASE_VIEW` 不再走 Action，改为反射直调：
```java
Class<?> cls = Class.forName("com.intellij.database.view.DatabaseView");
Method m = cls.getMethod("select", PsiElement.class, boolean.class);   // 懒加载 + 缓存
m.invoke(null, element, Boolean.TRUE);
```
`isActionAvailable(ACTION_SELECT_IN_DATABASE_VIEW)` 相应改为判断 `DatabaseView.select` 是否可取到。

### 修复 2：`resolveDbElement` 加三级兜底 + 失败日志
1. 数据源：`findDataSource(name)` → 失败 `findDataSourceLoosely`（忽略大小写 / 忽略或补齐 `@host` / 唯一数据源兜底）
2. 表：优先 `DbDataSource.getNameIndex().getObjectsByNameInsensitive(name)` 过滤 `DasTable`（不依赖 introspection level、不受 schema 限定影响）→ 回退 `DasUtil.getTables`
3. 元素：`DbDataSource.findElement(DasObject)` → 回退 `DbPsiFacade.findElement(DasObject)`，**必须精确签名**（DbDataSource 还有 `findElement(ObjectPath)` 重载）
4. 失败 `LOG.warn` 打印当前可用数据源列表

### 修复 3：`TableNavigator.performAction` 返回 `Result`（含失败原因），`KanbanBoard.navigateToTable` 直接展示原因

### 新增踩坑
- 合成 `AnActionEvent` 不是万能的：依赖 `SelectInContext` / `CONTEXT_COMPONENT` / `VIRTUAL_FILE` 的动作（Select In / 定位类）会置灰。

- `PSI_ELEMENT_ARRAY` 正确归属是 `PlatformCoreDataKeys.PSI_ELEMENT_ARRAY`（`LangDataKeys extends PlatformCoreDataKeys` 也能解析）；
  写成 `CommonDataKeys.PSI_ELEMENT_ARRAY` 编译报"找不到符号"。（首次编译失败就是踩了这个）
- 已在 241 上复核通过：`DatabaseView.select(PsiElement,boolean)`、`DbPsiFacade.{getDataSources,findDataSource,findElement}`、
  `DbDataSource.{getNameIndex,findElement(DasObject)}`、`ModelNameIndex.getObjectsByNameInsensitive(String)`、`DbElement extends PsiFileSystemItem`。

## 追加（同日）：修掉子菜单父项的粉色高亮 + 深色模式适配（用户已确认）

### 根因
- IntelliJ 只为 `JMenuItem` 提供了自己的 UI（`DarculaMenuItemUIBase` 系列），**`JMenu` 仍走 Swing L&F**，
  选中背景取 `Menu.selectionBackground` —— macOS 下就是**系统强调色**（用户设为粉色 → 整行变粉）。
- `UIManager.put("Menu.selectionBackground", ...)` patch 不可靠：`BasicMenuItemUI.installDefaults()`
  会把 `selectionBackground` 缓存进字段，UI 安装后再改默认值不生效。

### 修复：`BoardContextMenu.FlatMenu`（新增内部类）
关键发现 —— `BasicMenuItemUI.paintBackground` 只有 `menuItem.isOpaque()` 为 true 时才填充背景：
```java
if (menuItem.isOpaque()) {
    if (model.isArmed() || (menuItem instanceof JMenu && model.isSelected())) {
        g.setColor(bgColor);        // ← 系统强调色
        g.fillRect(0, 0, menuWidth, menuHeight);
    }
}
```
所以：
```java
setOpaque(false);                        // ★ 让 L&F 跳过背景填充（消除粉色）
// paintComponent: 自己 fillRect(JBColor.background()) 后调 super.paintComponent(g)
//                 → 文字 + 右侧箭头仍由 L&F 画，对齐/字体/箭头样式与兄弟项完全一致
```
**没有采用"完全自绘"**：完全自绘要自己算 textX / 箭头 / preferredSize，容易与兄弟项文字左边界
对不齐（`Menu.border` 与 `MenuItem.border` 的 insets 可能不同），还可能影响弹窗宽度。

同时把 `MENU_HOVER_FOREGROUND` 从固定深蓝 `#2470B0` 改为 `JBColor` 双态
（浅色 `#2470B0` / 深色 `#4A90E2`），深色主题下对比度更好，且与 `FlatCheckBoxMenuItem.CHECKED_FILL` 色系一致。

`buildConnectionMenu` 的「关系类型」子菜单（同一根因）也一并改用 `new FlatMenu(...)`。

编译 `./gradlew compileJava` BUILD SUCCESSFUL。剩余 3 条 lint 为 warning 且均为改动前既有模式
（styledPopupMenu/styledMenuItem 8 行重复、固定白色对勾 `new Color(0xFFFFFF)`、FlatCheckBoxMenuItem 的
`x` 参数恒为常量），非本次引入的错误。
文档：DEVELOPMENT_GUIDE 第 46 节。

## ★ 更正（同日）：上面的 `setOpaque(false)` 方案**无效**，已改为完全自绘

用户反馈"还是粉色的啊"，而且**粉色跑到了普通菜单项**（`同步表结构`）上 —— 说明不是单个组件的问题。

### 真正的根因（反编译字节码确认）
1. JDK `BasicMenuItemUI.paint` 把 **UI 字段 `selectionBackground`** 传给 `paintBackground`；
   而 `paintBackground` 在 `opaque=false` 时仍有 `else if (armed||selected) { fillRect(bgColor) }` 分支 → **照样填色**。
2. IntelliJ 的菜单 UI 在 `installDefaults()` 里**直接覆盖**该字段：
   - `com.intellij.ui.plaf.beg.BegMenuItemUI`（JMenuItem 用）
   - `com.intellij.ui.plaf.beg.IdeaMenuUI`（JMenu 用，继承 BasicMenuUI）
   ```java
   selectionBackground = JBColor.namedColor("Menu.selectionBackground",
                                            UIUtil.getListSelectionBackground(true));
   ```
   - `JBColor.namedColor` 结果**全局缓存**（首次解析后固定）→ 我们 patch 的 `UIManager` 值永远读不到；
   - `IdeaMenuUI.fillBackground()` 里 hover 填充 `paintHover()` 在 `isOpaque()` 判断**之外**，无条件执行。
3. 所以之前所有"改 UIManager / client property / setOpaque(false)"的做法全部无效，粉色 = 系统强调色。

### 最终修复：菜单项全部自绘，`paintComponent` 内**不调用 `super`**（L&F 绘制完全不发生）
`BoardContextMenu`：
- 新增 `FlatMenuItem extends JMenuItem`（普通项：复制/同步/查找用法/删除表…）
- `FlatMenu extends JMenu`（子菜单母项：跳转/关系类型，多画右侧箭头）
- `FlatCheckBoxMenuItem`（原有勾选项，改成同一套配色）
- 三者共用静态方法 `paintMenuRow(g, row, highlighted, withArrow)` + `menuRowPreferredSize(row, withArrow)`，
  保证文字左边界/行高/配色完全一致
- 统一常量：`ROW_TEXT_LEFT=12` / `ROW_TEXT_RIGHT=12` / `ROW_VERTICAL_PADDING=4` /

### 教训（务必记住）
- macOS 上"整行粉色"= **系统强调色**，先确认这个颜色是谁画的，再动手。
- IntelliJ 菜单 UI 会覆盖 Swing 的 `selectionBackground/selectionForeground`；
  `UIManager.put` + client property **都不可靠** → 想彻底控制菜单配色只能**自绘**。
- `setOpaque(false)` **不是万能开关**（JDK 有 else-if 分支；IntelliJ 的 fillBackground 完全无视它）。
- 自绘后必须自己重写 `getPreferredSize()`（父类按 L&F 的 checkIcon/accelerator 算，不可信）。
