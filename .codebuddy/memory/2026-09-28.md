# 2026-09-28

## Plugin Verifier 报 `UndoConstants` 无法解析（IU-263）→ 改反射降级

### 现象
用户在 IU-263.5701.42 上跑 Plugin Verifier：
```
Class not found (1)
  Access to unresolved class UndoConstants (1)
    Method EditorFileSync.setUndoDisabled(...) references an unresolved class UndoConstants.
    This can lead to NoSuchClassError exception at runtime.
```
本地开发环境是 **IU-241.19072.14**（`cat /Applications/IntelliJ IDEA.app/Contents/Resources/build.txt`），编译期发现不了。

### 根因
`UndoConstants.DONT_RECORD_UNDO` 在 2024.1 就 `@Deprecated`（见 09-24 的记录），263 直接删了类。
`EditorFileSync.setUndoDisabled` 里为了"恢复 VirtualFile 的撤销标记"硬引用了它
（因为 2024.1 没有 `enableUndoFor(VirtualFile)`，只能手动 `putUserData(key, null)`）。

### 改法
只依赖稳定公开 API，不稳的反射探测，取不到就降级：

- `Document`：`UndoUtil.disableUndoFor/enableUndoFor(doc)` —— 各版本都有且对称，直接用；
- `VirtualFile`：禁用用 `UndoUtil.disableUndoFor(file)`；恢复优先反射 `enableUndoFor(VirtualFile)`（新平台），
  否则反射清 `DONT_RECORD_UNDO`（`Class.forName` + `getField`，旧平台）；
- **新增 `canRestoreUndoFlag()` 门禁：恢复手段都拿不到时干脆不禁用** ——
  标记挂上清不掉会让该文件的撤销永久失效，比少一层保险严重。
- 反射 helper：`findStaticMethod(...)`、`findLegacyUndoKey()`，统一 `catch (Throwable) → null`。

### 验证
- `./gradlew compileJava` 通过、0 警告。
- `javap -v -p -classpath build/classes/java/main com.wd.editor.EditorFileSync | grep UndoConstants`
  只剩 `#239 = String ...` 一行（`Class.forName` 的字符串常量），**没有** `= Class ...` / 字段引用
  → 模拟 verifier 的判定依据，已经干净。
- 全量扫描 `build/classes/java/main/**/*.class` 也无其它类引用。
- 官方 `./gradlew verifyPlugin` 需联网下载 verifier 与目标 IDE（未在本地跑）。

### 教训
**"本地能编译" ≠ "兼容目标平台"**。带移除意向的 `@Deprecated` 平台 API（尤其常量类 / `Key`），
要么换等价新 API，要么反射延迟解析；否则就是"本地全绿、用户 IDE 运行时崩"。

### 文档
`DEVELOPMENT_GUIDE.md` 新增第 53 节（含上面的判定阈值与验证命令）。

## 同一份 verifier 报告里的另外两类问题（已修）

用户贴出完整报告，除 `UndoConstants`（compatibility problem）外还有：
internal API usage ×2、scheduled for removal ×1、deprecated ×8、override-only ×2。

### A. 内部 API：`FileEditorProviderSuppressor` → 删除（×2 警告）
- 报 `Internal interface usage: FileEditorProviderSuppressor` + `Internal method usage: isSuppressed(...)`。
- **顺带发现 9-24 的结论是错的**：当时说"`HIDE_*` 挡不住平台文本编辑器、只有 suppressor 能"。
  反编译 `FileEditorProviderManagerImpl.postProcessResult`：`hideOther` 的 removeIf 谓词是
  `policy != HIDE_OTHER_EDITORS` → **排他语义，会把平台文本编辑器一起移除** ✓。
  错因：把 `HIDE_DEFAULT_EDITOR`（只管 `DefaultPlatformFileEditorProvider`）与 `HIDE_OTHER_EDITORS` 混为一谈。
- 处理：删除 `DataChartTextEditorSuppressor.java` + plugin.xml 的 `<fileEditorProviderSuppressor>` 注册，
  只靠 `DataChartEditorProvider` 的 `HIDE_OTHER_EDITORS`（公开枚举值）。
- ⚠️ **回归风险**：HIDE_OTHER_EDITORS 单独生效此前未实测过 → 需用户 runIde 确认 IDE 层只有一个 tab。

### B. override-only：`AnAction.update()` / `actionPerformed()` → `ActionUtil` 公开入口（×2 警告）
位置：`TableNavigator.performDatabaseAction`（09-23 曾按"无等价公开入口"保留调用 + `//noinspection`）。
- 判可用性：`ActionUtil.lastUpdateAndCheckDumb(action, event, false)`，再读 `event.getPresentation().isEnabled()`；
- 执行：`ActionUtil.invokeAction(action, dataContext, ActionPlaces.POPUP, null, null)`；
- 检查抛异常时不当作"不可用"，而是跳过判断直接尝试执行（避免版本/线程差异让功能失灵）；
- `ActionUtil.doPerformActionOrShowPopup` 是 `@ApiStatus.Internal`，不能用。
- 字节码自查：全项目已无 `AnAction.update / actionPerformed / beforeActionPerformedUpdate` 直接调用。

### C. 还差用户提供的信息
"8 个 deprecated + 1 个 scheduled for removal"是**相对 IU-263** 的，本地 241 编译无任何 deprecation 输出，
列不出来 → 已请用户展开报告中这两节（或给 HTML/JSON 报告）。

### 状态
`./gradlew compileJava` 通过、0 警告；两处新改动都用 `javap -v` 做了"没有类引用/没有 override-only 调用"的自查。

## 2024.1.7（IU-241.19416.15）报告逐项核对（用户贴的展开版）
| 报告项 | 处理 |
| --- | --- |
| Internal interface/method: `FileEditorProviderSuppressor` / `.isSuppressed(...)` | 已删实现+注册 ✅ |
| Scheduled for removal: `UndoConstants` / `UndoConstants.DONT_RECORD_UNDO` | 已改反射降级（无硬引用）✅ |
| Override-only: `AnAction.update`（241 只报 update，263 还报了 actionPerformed） | 已换 `ActionUtil.lastUpdateAndCheckDumb` + `invokeAction` ✅ |
| Experimental: `FileEditorPolicy.HIDE_OTHER_EDITORS` | **保留**（取舍见下）⚠️ |

**新发现（重要）**：241 里 `HIDE_OTHER_EDITORS` 带 `@ApiStatus.Experimental`（javap 确认：
`HIDE_OTHER_EDITORS`/`PLACE_AFTER_DEFAULT_EDITOR` 带注解，`PLACE_BEFORE_DEFAULT_EDITOR`/`NONE`/`HIDE_DEFAULT_EDITOR` 没有）。
四个方案对比后决定**保留 HIDE_OTHER_EDITORS**：
- suppressor → 2 条 internal（"不得在平台外使用"，更严重）；
- 什么都不做 → IDE 层多一个纯文本 Text tab（用户明确不喜欢）；
- `FileType.isBinary()=true` → 0 警告，但 .datachart 变二进制：丢文本 diff、搜不到，JSON 文件不能接受；
- 现方案 → 1 条 experimental warning，241 报告总体仍是 Compatible；**263 的报告里已无 experimental 一节 → 新版已转正**。

核对过新用的 API 无注解问题：`ActionUtil.lastUpdateAndCheckDumb` / `invokeAction` / `UndoUtil.disableUndoFor`(两版) /
`enableUndoFor(Document)` 在 241 都没有 Internal/Experimental/Deprecated 注解（javap -v 逐个查过）。

另注：报告里 "Dependencies used → (failed) module intellij.profiler.common" 是 `com.intellij.database` 在 IU 里的
传递依赖解析问题，不在我们可控范围，且总体结论 Compatible，暂不处理。

## 2023.2（IU-232.10335.12）报告：字段还不存在 → 反射降级
**Compatibility problem**：`Field not found: FileDocumentManagerListener.TOPIC`
（`EditorSaveAllHook.<init>` 里的 getstatic → 老 IDE 上会 `NoSuchFieldError`）。
原因：该 Topic 字段是**后来才加进平台**的；而 `since-build="223"` 让 verifier 逐个构建检查到 2023.2。

- 修法：`EditorSaveAllHook` 里 Topic 改**反射**（`FileDocumentManagerListener.class.getField("TOPIC")`），
  拿不到就 `return` 不注册钩子 —— 2023.2 及更早只有"平台 Save All 补位保存"这条失效，
  画布自己的 Cmd/Ctrl+S 保存照常（钩子本是双保险）。
- 备选（未采用）：把 `since-build` 提到 233，代价是丢 223~232 用户。
- 字节码自查：`javap -c ... EditorSaveAllHook | grep FileDocumentManagerListener.TOPIC` 为空 ✓（只剩反射字符串）。
- **与 UndoConstants 是同一类坑的两个方向**（一个被删、一个还没加）：跨版本支持时新增/删除字段都不能硬引用。
- 2023.3.8（IU-233.x）报告只有 "1 usage of experimental API"（即 HIDE_OTHER_EDITORS），无其它问题 ✓。
- 文档：新增 DEVELOPMENT_GUIDE 第 53.5 节。`./gradlew compileJava` 通过、0 警告。
