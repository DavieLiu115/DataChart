## 修复 Win 系统子菜单宽度不够

**问题**：连线右键菜单的"关系类型"子菜单，Win 系统下"一对多/多对多"文字被截断。

**根因**：`BoardContextMenu.FlatCheckBoxMenuItem` 自绘 `paintComponent` 接管渲染后，父类 Swing 的 `BasicMenuItemUI.getPreferredSize()` 依赖 `checkIcon` 计算宽度，但本组件已经关掉了默认 checkIcon → 子菜单宽度按 0 icon 宽算，导致文字被截。

**修复**：重写 `getPreferredSize()`，手动算 `BOX_LEFT_PADDING(18) + BOX_SIZE(14) + 6 + 文字宽度 + 右边距(12)`，高度 `max(BOX_SIZE+8, fm.getHeight()+6)`。

**教训**：自绘 `paintComponent` 接管 Swing JMenuItem/JCheckBoxMenuItem 后，父类 L&F 算 `getPreferredSize()` 不可信，必须自己实现，否则 Win L&F 下子菜单宽度会按 icon=0 算 → 文字截断。

**改动**：
- `src/main/java/com/wd/ui/BoardContextMenu.java` 新增 `FlatCheckBoxMenuItem.getPreferredSize()`
- `DEVELOPMENT_GUIDE.md` 第 29 节追加踩坑记录

## 修复 Win 系统左键不能起手连线

**问题**：Win 系统下从列行按下左键拖动鼠标到终点，松手后不会自动连线，必须右键起手才行。

**根因**：`KanbanBoard.mousePressed` 列行分支只在右键 (`isPopupTrigger || BUTTON3`) 才设置 `isConnecting=true`；左键点击列只调 `toggleRowSelection`（列高亮）。Mac/Win 现代 GUI 默认是左键拖拽，所以左键被"拦截"了。

**修复**：用"待连线状态 + 移动阈值升级"方案，避免破坏原有列高亮交互：
- 新增 `pendingConnectionSource / pendingConnectionSourceRow / pendingConnectionPressPoint` + `CONNECTION_DRAG_THRESHOLD=4`
- `mousePressed` 左键列行：只设 pendingConnection*，不入 `isConnecting`
- `mouseDragged`：pending 状态下计算 `dx²+dy² >= 16` 才升级为 `isConnecting=true`
- `mouseReleased`：pending 未升级就 `toggleRowSelection`（保持原列高亮交互）；升级了就走原有 `addConnection` 逻辑

**改动**：
- `src/main/java/com/wd/ui/KanbanBoard.java` 字段 + 三个 mouse 事件分支
- `DEVELOPMENT_GUIDE.md` 第 30 节追加

**教训**：GUI 拖拽交互的"点击 vs 拖拽"歧义要用阈值延迟判定（移动距离），不能简单根据鼠标按键硬切。左键起手拖拽是现代 GUI 默认，应优先支持。

## 修复连线松手点飘走导致连接丢失

**问题**："鼠标移到 leader 行没点击，点一下别处连接就没了"——拖拽中预览高亮正确显示 leader 行，但松手时鼠标飘到空白处，原 `mouseReleased` 用松手点找 `targetCard`，找不到就不 addConnection，用户视觉上"连接没了"。

**根因**：松手点 ≠ hover 目标。用户在拖拽过程中目标已经选好（leader 行），但松手点飘到别处时 `findCardAt(e.getPoint())` 找不到目标卡片。

**修复**：记录最后一次 hover 的目标，松手优先用：
- 新增 `lastHoverTargetCard / lastHoverTargetRow`
- `mouseDragged` isConnecting 分支命中目标行时写入
- `mouseReleased` 优先用 lastHoverTarget，无效才回退到松手点
- 进入连线时清空 lastHoverTarget（两个入口都清）

**改动**：
- `src/main/java/com/wd/ui/KanbanBoard.java` 字段 + mouseDragged/mouseReleased/mousePressed 三处清理
- `DEVELOPMENT_GUIDE.md` 第 31 节追加

**教训**：拖拽建线场景，松手点是次要的，hover 状态更准确反映用户意图。"最后有效 hover" 应作为建线目标，松手点仅在无 hover 时作为兜底。

## 修复连线建线后源行用户选中残留

**问题**：选中 `config_type` 行（橙色）→ 拖到 `invoke_target` 建线 → 点别处后 `invoke_target` 变淡黄，但 `config_type` 仍是橙色——用户期望建线后源行的橙色高亮应被清空。

**根因**：左键列行按下进 pendingConnectionSource → 升级为 isConnecting 时没调 toggleRowSelection，源行 `highlightedRows` 一直保留，导致整条连线 + 源行都是橙色（连线色取自源行高亮色）。

**修复**：
- 新增 `clearUserRowSelection(card, rowIndex)`：从 `getHighlightedRows()` 移除该行；若是 activeHighlight 则 `clearActiveHighlight()`
- `mouseDragged` 升级分支 + `mousePressed` 右键列行起手分支都调 `clearUserRowSelection`
- 快速点击（未升级）仍走原 `toggleRowSelection`，保持 toggle 语义不变

**改动**：`BoardExportUtil.java` + `DEVELOPMENT_GUIDE.md` 第 33 节。

## 修复连线建线后颜色突变

**问题**：拖拽连线（粉色预览）→ 松手建线后整条线突然变成 palette 下一个颜色（如浅绿），源/目标行也变成新 palette 色——视觉跳变。

**根因**：
- mouseReleased 调 `addConnection(source, row, target, row)`（5 参版）
- 5 参版内部分配 palette 色作为连线 color
- 上一轮修复清掉了源行用户选中态，`resolveLineColor()` 找不到高亮色就回退到 palette → 跳变

**修复**：
- `addConnection` 新增 6 参重载 `(..., Color overrideColor)`：`overrideColor!=null` 用它作初始 color，否则 palette
- 5 参/4 参版委派到 6 参版传 null（兼容旧调用）
- 新增 `capturePreviewColor(card, rowIndex)` 从 `previewHighlightRows` 取出源行粉色并清掉
- `mouseReleased` 建线前取 preview 色作为 overrideColor 传入

**改动**：`KanbanBoard.java`（addConnection 重载 + capturePreviewColor + mouseReleased 调用）+ `DEVELOPMENT_GUIDE.md` 第 34 节。

## 撤回"沿用 preview 色"误改 + 教训

**撤回原因**：用户反馈"怎么能一直粉色呢？连一次换一个颜色啊"——所有新连线都是粉色，多条连线视觉无法区分（ER 图基本要求就是不同连线不同颜色）。

**教训**：粉色 `CONNECTION_PREVIEW_COLOR` 只是**拖拽过程临时色**，建线成功后必须从 palette 分配新颜色让多条连线视觉可区分。我之前误以为"建线后突然变色是跳变 bug"，其实是用户期望的"连一次换一种颜色"行为。

**正确设计**：
- 拖拽预览：粉色临时色
- 建线成功：从 `CONNECTION_COLOR_PALETTE[connectionColorIndex++ % palette.length]` 分配新颜色
- 加载文件 / 编程方式建线：也走 palette

**撤回动作**：
- 删掉 `addConnection` 6 参重载 + `capturePreviewColor` 私有方法
- mouseReleased 建线分支恢复为 `addConnection(src, srcRow, tgt, tgtRow)`（走 palette）
- 保留第 33 节（清源行用户选中态）——那是必要的修复
- `DEVELOPMENT_GUIDE.md` 第 34 节改为"撤销记录 + 正确设计"

**通用教训**：修复 UX 问题时必须从用户最终目标出发。ER 图工具的核心价值是"可视化区分多条连线"，任何让所有连线同色的修复都是反方向。修之前先想清楚"用户用这个工具想达成什么"。

## 连线预览色改为深灰

**需求**：用户反馈"从起点出来没连上，预览色不要用粉色了，用深灰色"。

**改动**：`KanbanBoard.CONNECTION_PREVIEW_COLOR` 从 `new Color(0xFFB6E1)`（粉色）改为 `JBColor(浅色 #757575, 深色 #AAAAAA)`。预览连线绘制处（原 `Color.PINK`）也统一改用 `CONNECTION_PREVIEW_COLOR`。理由：粉色与 palette 中粉紫 `#C8A2C8` / 粉红 `#FFB7B2` 系颜色太接近，预览时容易混淆。

**改动文件**：`KanbanBoard.java` + `DEVELOPMENT_GUIDE.md` 第 34 节补充。

## 焦点按钮 focus 改为"左上对齐"而非几何居中

**需求**：用户反馈 focus 展示不对，最左边卡片（连线/卡片）被截或留白过多，期望"最左边展示出来"。明确要求：不自动缩放、不管右边，只要从最左边开始展示。

**改动**：`BoardViewport.focusOn(cards, w, h)` 算法从"几何居中"改为"**左上对齐**"：
- 计算所有卡片合并包围盒左上角 `(minX, minY)`
- 平移 transform 让 `(minX, minY)` 落到视口左上角 + `FOCUS_PADDING(20)` 屏幕像素
- 不再计算内容中心/视口中心，右侧/下方超出部分不做缩放、由用户滚动查看
- 新增常量 `FOCUS_PADDING = 20`
- 同步更新 `KanbanBoard.focusView()` 注释、`DataChartView.loadFromJson` 加载后注释、focusButton tooltip 文案

**核心文件**：`BoardViewport.java`（focusOn + 常量）、`KanbanBoard.java`、`DataChartView.java`、`DEVELOPMENT_GUIDE.md` 第 16 节。

## oneOneButton 实现"1:1 缩放 + focus 定位"

**需求**：点击工具栏 "1:1" 按钮，先把缩放比调整为 1:1，再调用 focus 调整位置。

**改动**：
- `BoardViewport.setZoomFactor(viewCenterX, viewCenterY)`：新增，直接设缩放因子，复用 `zoom()` 传 scaleFactor=`1/当前zoom`，以视口中心为锚点（保持中心内容不位移）
- `KanbanBoard.setZoomTo1()`：新增，取 `getVisibleRect()` 中心，调 `viewport.setZoomFactor`，成功则 notifyViewChanged + repaint
- `DataChartView.setupToolBarButtons()`：给 `oneOneButton` 挂监听，先 `setZoomTo1()` 再 `focusView()`（最左/最上对齐）
- tooltip："缩放为 1:1，并聚焦到最左/最上卡片"

**核心文件**：`BoardViewport.java`、`KanbanBoard.java`、`DataChartView.java`、`DEVELOPMENT_GUIDE.md` 第 16 节。

**教训**：1:1 缩放 + 对齐定位组合时，缩放要复用 `zoom()` 锚点机制（保证中心不跳变），再单独 focus 定位，两步动作分离职责更清晰。

**教训**：ER 图工具的 Focus 功能，用户的预期往往是"把内容从画板原点开始、贴着左上角展示"，方便按图布局查看，而不是数学上把内容中心挪到屏幕中心（那样会引入不确定的左右留白/截断）。
