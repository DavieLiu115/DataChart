## DataChart 卡片 ID 用 UUID 改造（需求：拖入重复表重开后连线错乱）
用户反馈：拖入两张 `sys_user`，关闭再打开后所有指向 `sys_user` 的连线都连到第一张卡上 → 线乱了。

### 根因
- `DatabaseTableMetadataFetcher` 三处（listTables / fetchTableInfo / fetchTableInfoByElement）都用 `String id = schema + "." + name;` 生成卡片 id
- 同一张表拖入两次时 id 完全相同
- `BoardPersistence.loadFromChartData` 用 `findCardById` 按 id 查卡 → cards List 第一个匹配命中 → 所有连线指向第一张

### 修复
- `TableInfo.id` 从 `final` 改为可写，新增 `setId(String)`
- `KanbanBoard.addTableCard` 创建 KanbanCard 前 `info.setId(UUID.randomUUID().toString())`，源头保证唯一
- `KanbanBoard.loadFromChartData` 遍历 tables 时调 `isCardIdExists` 检测重复 id，重复就补 UUID 并 `model.setId` 写回内存（下次保存即规范化）
- 旧文件首次打开：第一张 `public.sys_user` 保持原 id（指向它的旧连线仍正确），后续重复表补 UUID
- `BoardPersistence` / `Connection` / `ChartRelation` 全部不动 —— `fromCardId` 字段本身就是 string，向后兼容

### 设计原则（写进 DEVELOPMENT_GUIDE 第 35 节）
- **数据标识用 UUID 不业务字段**：避免同表重复 / 跨库同名表冲突
- **拖入时分配，不靠加载时补救**：源头避免冲突
- **加载时检测 + 补 UUID + 同步 model.setId**：旧文件首开 + 保存一次后根治

### 已修复：syncTableStructure 连线列错位
- **问题**：`KanbanBoard.syncTableStructure`（表头右键"同步表结构"）用 `setTableInfoWithDiff` 替换 TableInfo，但 `Connection.sourceRow/targetRow` 存的是**列 index**。同步后列顺序可能变化（增删列），沿用旧 index 会让连线指向错误列（与已修的"删除列后 index 错位"同源）。
- **修复**：
  - `Connection.sourceRow/targetRow` 从 `final` 放开为可变，新增 `setSourceRow/setTargetRow`
  - `syncTableStructure` 替换前记录涉及该卡片的连线的列名，替换后用 `findColumnIndex` 按列名在新结构中重定位 index；列被删除则移除该连线
  - 新增辅助方法 `oldRowToColumnName` / `findColumnIndex`
- **编译**：`./gradlew compileJava` BUILD SUCCESSFUL，0 lint

### 审查发现的其它问题（未修，供后续参考）
- **`DataChartEditor.dispose()` 强制保存**：`if (modified) saveDocument();` —— 关闭编辑器时改动会被强制写盘，绕过 IDE 的"未保存确认"。若用户点关闭但不保存，改动仍落盘。是否为预期自动保存设计需确认。
- **`KanbanBoard.addCard` 平铺规则**：用 `4 * DEFAULT_CARD_WIDTH`(=800) 判断换行，与 `addTableCard` 的"4 张/行"逻辑不一致（不同路径可能算出不同布局），但两者互不调用、影响有限。
- **`TableDropHandler.getName` 反射**：依赖 `dbElementClass.getMethods()` 遍历找 `getName`，性能一般但命中即返回，无 bug。
- **连线命中判定 `hitTestConnection`**：矩形近似，对长斜线/贝塞尔曲线误命中率偏高（点落在矩形包围盒内即算命中），属已知简化。
- **`DatabaseTableMetadataFetcher.findTable` 用 `equalsIgnoreCase` 而 `fetchTableInfo` 的 id 用精确 schema.table**：跨大小写可能有轻微不一致，实际场景少。
- **潜在**：`drawTableCard` 卡片高度上限 400，列很多时 `maxRows` 截断显示，连线若指向被截断的行仍能画（index 越界返回 null 会跳过画线），不会崩。
- **导出 scale 降级**：`exportToImage` 内存不足自动降 scale，已 OK。

## 修复：重新打开 .datachart 视口错位（2026-08-07 晚）
### 现象
IDE 退出前打开了 .datachart，再次启动自动重开时卡片整体跑到画板顶部/角落，必须手动点 Focus 按钮才能恢复。

### 根因（两层）
1. `DataChartEditor.getComponent → ensureInitialized → loadFromFile` 是同步链路
2. `loadFromJson` 用 `SwingUtilities.invokeLater` 一帧延迟调 `focusView`，但**一帧后 panel 仍未真正完成 Swing 布局**（还没嵌入 IDE 编辑区）
3. `KanbanBoard.getVisibleRect()` 返回 0×0
4. `BoardViewport.focusOn` 进入"fits=true"分支，把内容中心对齐到 (0,0) → `transform.translate` 把视口推到负方向
5. panel 真正显示时，画面跑到顶/左外

### 修复
- `KanbanBoard.focusView` 加 viewWidth/viewHeight 零值防御
- `DataChartView.loadFromJson` 改用 `ComponentAdapter` 监听首次 `componentResized`，拿到有效尺寸后再 `focusView`，触发后立即注销
- `scheduleFocusWhenReady()` 方法 + `focusWhenReadyListener` 字段
  - 已有有效尺寸直接 focus
  - 否则注册 listener（多次调用移除旧的避免累积）
  - `dispose()` 清理 listener 防止内存泄漏
- 编译 + 0 lint 验证通过

### 教训
- **`invokeLater` 不等于"等组件布局完成"**：在 `getComponent` 同步链路里调用的代码，下一帧 panel 还没真正显示
- **focusOn 这类依赖 viewWidth/viewHeight 的算法必须零值校验**：0 会被当成"放得下"产生灾难性偏移
- **Swing 监听器必须管理生命周期**：跨多次 load + dispose 都要清理
