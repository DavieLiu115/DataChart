## 7-31 实现看板（参考 DragableBoard 简化版）

### 需求
在 DataChartView 的 dataView 区域实现一个看板，参考 DataHelper 项目的 `DragableBoard.java`，但不要它那个数据库菜单（添加表、开启动画、复位、放大、缩小、网格、连线模式、删除表、导出连线数据、导入连线数据）。

### 实现方案
- **新建 `KanbanCard.java`**：图表卡片元素，按图表类型配色（line=蓝、bar=橙、pie=绿、scatter=紫、default=灰），支持标题、类型徽标、描述文字换行、阴影、圆角、选中态边框
- **新建 `KanbanBoard.java`**：简化版 DragableBoard（~330 行 vs 原 2000+ 行），保留核心能力：
  - 平移：空白处拖拽
  - 缩放：Ctrl+滚轮（Mac 也支持捏合手势）
  - 卡片拖拽：拖动卡片移动位置
  - 网格背景：自动主题色适配
  - 空格键复位视图
  - 自动平铺布局
- **去掉**：数据库表、连线（Connection/BoardElement）、光点动画、PDF 导出、图片导出、文本选择、右键菜单、persistence、i18n、NotificationUtil
- **修改 `DataChartView.java`**：新增 `initKanbanBoard()`，把 KanbanBoard 放入 dataView 区域，加载示例卡片（4 种图表类型各一张）

### 关键设计决策
- KanbanCard 自带 `isDark` 参数绘制，自动适配 IDEA 深色/浅色主题
- KanbanBoard 用 `JBColor` 一次性绑定主题色，避免运行时检测

## 7-31 KanbanBoard 支持 Mac 触控板两指水平/垂直移动

- 原 `mouseWheelMoved` 只处理垂直平移，缺少水平轴
- 新增 `panByWheel(e, wheelRotation)` 方法，统一处理平移逻辑：
  - 垂直：`transform.translate(0, -rotation * 20 / zoomFactor)`
  - 水平：Shift+滑动 → `transform.translate(deltaY, 0)`（Mac 触控板横向滑动由 JDK 报告为 Shift+滚轮事件）
  - 除以 zoomFactor 保证缩放后跟手
- Mac 与非 Mac 分支都复用 `panByWheel`，消除代码重复
- 踩坑：Java AWT 的 MouseWheelEvent 没有专门的横向滚动 API，只能通过 `e.isShiftDown()` 检测横向滑动（这是 JDK 在 Mac/Windows 上的统一行为，IntelliJ 也是这么做的）

## 8-1 修复拖拽 ClassNotFoundException: DbNamedElement

- **报错**：`TableDropHandler.ensureDbClasses()` 里 `Class.forName("com.intellij.database.psi.DbNamedElement")` 抛 ClassNotFoundException，导致拖表不生成图
- **根因（反编译确认）**：`DbNamedElement` 类在 **2023.2.6 和 2025.3 的 Database API 中都不存在**（之前反编译失败是因为类不存在，不是 classpath 问题）
  - `database-plugin.jar` / `database-plugin-frontend.jar` 里只有 `DbElement` 和 `DbTable`
  - `DbElement` 接口本身无 `getName()`，但继承 `com.intellij.psi.PsiFileSystemItem`（有 getName）
- **修复**：
  - 移除 `dbNamedElementClass` 字段和 `DbNamedElement` 类加载
  - `getName()` 改用 `findMethodByName(dbElementClass, "getName")` 反射查找继承的 getName 方法
- **关键教训**：反射访问第三方插件类时，必须先反编译确认类真实存在和完整类名，不能凭 API 文档猜测；不同版本（2023.2 vs 2025.3）Database API 有差异

## 8-1 关键修复：attachedObject 不是 DbElement（拖拽取数据方式错误）

- **日志**：`[DnD] attachedObject is not a DbElement, ignore` → 拖拽对象类型判断失败
- **反编译 DbElementDnDTarget 字节码确认**：Database 工具窗口拖拽时，元素**不是** `getAttachedObject()` 直接返回的
  - 正确方式：`DnDEvent.getTransferData(DnDEventImpl.ourDataFlavor)` 返回 `Object[]`，**数组元素**才是 `DbElement`（如 DbTable）
  - 关键字节码：`event.getTransferData(DnDEventImpl.ourDataFlavor)` → `tryCast(Object[].class)` → `Object[]`
- **修复 `TableDropHandler`**：
  - 新增 `findFirstDbElement(DnDEvent)`：遍历 Object[] 找 DbElement
  - 新增 `extractObjects(DnDEvent)`：反射获取 `DnDEventImpl.ourDataFlavor` 静态字段 → `getTransferData` → 转 Object[]
  - `update()`/`drop()` 改为用 `findFirstDbElement`，不再判断 `getAttachedObject()`
- 编译通过
- **关键教训**：IntelliJ DnD 拖拽数据可能通过 DataFlavor 提供（Object[]），不能只看 getAttachedObject()；一定要反编译目标端实现（DbElementDnDTarget）确认真实取数方式

## 8-1 关键修复：DasUtil.getColumns(DasObject) + JBIterable

- **日志**：`NoSuchMethodException: DasUtil.getColumns(DasTable)` + 卡片无字段
- **反编译 2023.2.6/2025.3 DasUtil 确认**：
  - `getColumns(DasObject)` 参数类型是 `DasObject`（不是 `DasTable`），但 `DasTable extends DasObject` 可以传入
  - `getTables(DasDataSource)` 也是同样模式

- 编译通过，无错误
- **关键教训**：反射调用第三方插件时，反编译**返回值类型**也很重要；`JBIterable`（JetBrains 自定义 Iterable）返回时不能用 `instanceof Collection` 判断
