# 2026-08-03 工作日志

## 需求 27：relations 存储列 index 改为新增列名定位（删除列后连线错位）

### 用户反馈
- relations 里 fromColumn/toColumn 存的是列的 index（字符串数字如 "12"），删除列后就不准确了
- 期望：加一个列的名称，删除列后仍能准确定位

### 实现
- **`ChartRelation`**：新增 `fromColumnName` / `toColumnName` 字段（可空，向后兼容旧文件）
  - 旧字段 `fromColumn`/`toColumn` 保留（仍存列 index，兼容读取）
- **`BoardPersistence.toChartData`（保存）**：额外写入列名
  - 新增 `resolveColumnName(card, row)`：从卡片行 index 取 `TableInfo.columns[row].name`，行越界/非表格卡返回 null
- **`BoardPersistence.loadFromChartData`（加载）**：新增 `resolveRowIndex(card, columnName, columnIndexStr)`
  - 优先级：① 提供 columnName 且卡片中存在该列名 → 用该列 index；② 否则回退解析旧 columnIndexStr；③ 都失败 -1

### 关键设计
- **向后兼容**：旧 .datachart 无列名字段 → 回退用旧 index，行为不变；新文件带列名 → 增删列后仍准确
- **列名优先，index 兜底**：即使列名丢失/不存在，也不至于连线丢失，尽量保留旧行为

### 教训
- **模型加字段要保留旧字段兼容**：不能直接删掉旧 index 字段，否则旧文件反序列化后连线全丢；加新列名 + 解析时优先列名、回退 index
- **fastjson 通过 getter/setter 序列化**：新增字段只需补 getter/setter 即可自动进 JSON
