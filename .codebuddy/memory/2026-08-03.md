## 需求 27：relations 存储列 index 改为新增列名定位（删除列后连线错位）

### 用户反馈
- relations 里 fromColumn/toColumn 存的是列的 index（字符串数字如 "12"），删除列后就不准确了
- 期望：加一个列的名称，删除列后仍能准确定位

### 实现
- **`ChartRelation`**：新增 `fromColumnName` / `toColumnName` 字段（可空，向后兼容旧文件）
  - 旧字段 `fromColumn`/`toColumn` 保留（仍存列 index，兼容读取）
- **`BoardPersistence.toChartData`（保存）**：额外写入列名
  - 新增 `resolveColumnName(card, row)`：从卡片行 index 取 `TableInfo.columns[row].name`，行越界/非表格卡返回 null
- **`BoardPersistence.loadFromChartData`（加载）**：新增 `resolveRowIndex(card, columnName, columnIndexStr)`
  - 优先级：① 提供 columnName 且卡片中存在该列名 → 用该列 index；② 否则回退解析旧 columnIndexStr；③ 都失败 -1

### 关键设计
- **向后兼容**：旧 .datachart 无列名字段 → 回退用旧 index，行为不变；新文件带列名 → 增删列后仍准确
- **列名优先，index 兜底**：即使列名丢失/不存在，也不至于连线丢失，尽量保留旧行为

### 教训
- **模型加字段要保留旧字段兼容**：不能直接删掉旧 index 字段，否则旧文件反序列化后连线全丢；加新列名 + 解析时优先列名、回退 index
- **fastjson 通过 getter/setter 序列化**：新增字段只需补 getter/setter 即可自动进 JSON

### 教训
- **final 字段不能做缓存失效**：linkedRowsCache 原是 final，要复用缓存需改非 final（initial null），否则"无法为最终变量赋值"
- **缓存要区分静态元数据 vs 动态数据**：反射 Method（静态）可安全缓存；数据源/表对象（运行时可变）缓存有脏数据风险，不做
- **.form 绑定依赖 DialogWrapper.init()**：改继承前必须先确认 GUI Designer 表单编译机制，否则字段全 null
- **IconLoader.getIcon() 已是延迟加载**：图标字段对象轻量，真正的优化是删无用字段而非改加载方式

## 需求 28：新建 .datachart 文件头部加给 AI 的使用说明

### 用户反馈
- 新建 datachart 文件时，在文件前面加一段注释，告诉 AI 怎么使用这个文件

### 实现
- **JSON 不支持原生注释** → 用 JSON 字段 `_aiGuide` 承载说明，不影响 fastjson 解析
- **`ChartData`** 新增 `aiGuide` 字段（声明在 `version` 前 → 序列化靠前输出到文件头部）+ getter/setter
- **模板 `fileTemplates/DataChart.datachart.ft`**：头部加 `_aiGuide` 详细说明（用途、tables/relations 结构、列名定位提示）；顺带修正 `"charts": []` → `"tables": []` + `"relations": []`（原来模板用 charts 与模型 tables 不一致）
- **传递链（关键）**：`DataChartView` 加载时 `data.getAiGuide()` 暂存到 `DataChartView.aiGuide` 字段，保存时 `serializeToJson` 用 `data.setAiGuide(aiGuide)` 写回
  - 原因：`KanbanBoard.toChartData()` 每次新建 ChartData，aiGuide 不会自动保留，不暂存会丢失
- fastjson 默认不序列化 null → 旧文件无 `_aiGuide` 不影响；新文件带说明持久化

### 教训

## 需求 29：关系类型默认值 + 勾选框浅色主题优化

### 1. 连线默认关系类型改为"一对一"
- 背景：新连线默认 `RelationType.UNKNOWN`（渲染=多对多三叉），用户要求默认一对一
- 改动（UNKNOWN → ONE_TO_ONE）：
  - `Connection`：字段默认值、无参构造、6 参构造 null fallback、`setRelationType` null fallback
  - `KanbanBoard.addConnection` 无参重载默认值
  - `BoardPersistence.loadFromChartData`：null 或 UNKNOWN 统一回退 ONE_TO_ONE（旧文件兼容）
- 说明：UNKNOWN 在 Connection.paint 被当"多对多"渲染，故默认与加载回退都指向一对一

### 2. 勾选框浅色主题对比度优化
- 问题：关系类型子菜单 JCheckBoxMenuItem 浅色主题下默认勾选框是 Gray._40 深灰填充，看不出勾选
- 方案：新增 `BoardContextMenu.FlatCheckBoxMenuItem`（继承 JCheckBoxMenuItem）重写 paintComponent 完整自绘 cell：
  - 选中：蓝底(JBColor 浅#2470B0/深#4A90E2) + 白对勾(drawPolyline)
  - 未选中：填充(白/#3C3F41) + 1px 灰边(#B0B0B0/#6B6B6B)
  - 文字 JBColor.foreground() 从 18+14+6 处 drawString，FontMetrics 垂直居中
- 关键：setOpaque(true)+setBorderPainted(false) 绕开 BasicMenuItemUI 缓存的 checkIcon
- 踩坑：Swing CheckBoxMenuItem.checkIcon 从 UIDefaults 加载后被 BasicMenuItemUI 缓存，改 UIDefaults 不生效，必须自定义组件 paint
